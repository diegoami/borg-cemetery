# Balanced999 death/critical-recovery bank: preparation contract

Owner target: **999 distinct starts,111 per each of the nine classes**. This
file describes preparation; a bank is not called complete until all nine
harvests supply111 native-load-inspected, nonduplicate incident starts.

Candidate types: actual terminal deaths and observed critical-HP recoveries.
The latter require actual HP loss to≤25% maximum HP, living (including0HP),
and a later observation at≥50% HP. A max-HP increase alone is insufficient.
These are observed near-death candidates, not qualified null-move/counterfactual
lethality diagnoses. Source witness, minimum and recovery remain explicit.

Starts use the saved checkpoint at/before first visible threat or observable
unseen contact in the incident episode. The historical incident must fit within
2,000 engine ticks from that start. Native short-load inspection establishes
exact initial equipment/status without guessing how key/think logs align.
Keep full native saves, inventory, devices and spells. Deduplicate save bytes;
shared-life events remain correlated. Environmental deaths without supported
observable triggers remain captured but are visibly excluded from this bank.

`harvest-spec.json` prespecifies source/seed order, all races,100k-turn natural
cap, fixed checkpoint cadence, bounds and per-class quota. Sampling stops by
prespecified seed order once that class has111 usable starts. Every attempted
run, rejected candidate, native death and probe remains retained; selection is
not a population/survival-rate estimate. Within-class parallel completion speed
does not choose cases. Native namespaces are private per run to avoid the old
exporter's sequential-name races; canonical IDs are content-derived later.
